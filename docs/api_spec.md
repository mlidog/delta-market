> 本文件由公开资料调研得出，**尚未用真实 Token 验证**。M6 接入真实接口时逐条核对并更新。

## 一、来源

| 项 | 值 |
| --- | --- |
| 官方开放平台（申请 Token） | https://orzice.com/work/ |
| API 文档（Apifox） | https://work-api.apifox.cn |
| 官方 SDK 仓库 | https://github.com/orzice/DeltaForceApi |
| 交流 QQ 群 | 791785919 |

### 1.1 获取 Token 与查看价格的操作路径

1. 打开 https://orzice.com/work/ （开放平台首页）
2. 点右上角 **QQ登录**（或直接访问 https://orzice.com/login ），使用 QQ 扫码授权；
   这是查看价格与开通服务的必要前提，未登录时 https://orzice.com/work/home 只显示"需要登录才能访问"
3. 进入 **控制台**（登录后的 `/work/home`）
4. 在控制台内进入 **开通服务**，查看资源包档位与单价，并开通需要的接口
5. 开通后获取专属 **Token**，填入项目 `.env` 的 `DELTA_API_TOKEN`

开通接口时请勾选 MVP 需要的四个：`item_info_all`、`item_price_all`、`minute`（或 `hour`/`day`）、`item_list`。

官方安全提示：Token 不要暴露、务必在服务端请求、并做本地缓存。本项目已通过 `.gitignore` 阻止 `.env` 入库。

## 二、通用约定

| 项 | 值 |
| --- | --- |
| Base URL | `https://orzice.com/workApi` |
| 鉴权 | 查询参数 `token=<DELTA_API_TOKEN>` |
| User-Agent | `DeltaForceApi/1.0` |
| 响应信封 | `{"code": 0, "msg": "成功", "count": N, "data": ...}`，`code != 0` 视为业务失败 |
| 无权限 | HTTP 404（文档原话：请检查 token 是否正确） |
| 计费 | 按"资源次数"扣减：`item_info_all` 约 20 次，`item_price_all` 约 20 次，价格曲线 1 次 |

### 2.1 计费与套餐（2026-10-12 于控制台核实）

| 项 | 值 |
| --- | --- |
| 硬币汇率 | **¥1 = 1 硬币**（充值档位 ¥5 / ¥10 / ¥20 / ¥199 / 自定义，无批量折扣） |
| 套餐档位 | 20 硬币 / 3,000 次 · 199 硬币 / 220,000 次（仅此两档） |
| 单位成本 | 3,000 次档 ¥0.0066667/次 · 220,000 次档 ¥0.0009045/次（相差 7.37 倍） |
| 扣费规则 | **正确处理并返回数据才扣费；系统异常或未正常返回数据不扣费** |
| 官方建议 | 「为了确保您资源能更慢的消耗，您需要使您的网页具有数据缓存功能」 |

未正常返回也不扣费这一点，意味着客户端重试策略不会产生额外成本。

### 2.3 特勤处制造接口（2026-10-12 实测验证）

两个接口都只扣 **1 次资源/请求**，参数 `t` 为站点（1 技术中心 / 2 工作台 / 3 制药台 / 4 防具台）。

| 接口 | 参数 | 字段 |
| --- | --- | --- |
| `GET /v1/sjz_api/manufacturePro` | `t`、`l`（部门等级 1/2/3） | `period`、`priceMax`、`sxf`、`price`、`price_hour`、`unlockLevel` |
| `GET /v1/sjz_api/manufacture` | `t`（不区分等级） | `price`（利润）、`price_hour`（每小时利润）、`period` |

**实测结论（441 条真实数据）**：

1. **`price` 是净收益，不是"到手价"**。文档写"真实到手价格（已扣除手续费）"有误：
   实测 `priceMax(71469) − sxf(2131) ≠ price(16396)`，且 `price ÷ period` 精确等于 `price_hour`。
   官方接口同物品的利润值与之接近但**不完全一致**（抽样 6 条全部不同，差值数百到数千），
   符合"官方数据(不准) / Pro 自有源计算"的定位——两者都是利润，只是成本模型不同。
2. **推算材料成本** = `priceMax − sxf − price`。实测样本数量级合理
   （如参考价 13205 的物品推算成本 4233）。这是本项目唯一的成本口径，属于**反推值**，
   数据帝并未直接提供配方与材料成本。
3. **等级必须分开取**：同一物品在 L2 与 L3 的总收益可能相同，但制造时长不同
   （实测"重型突击背心" L2 = 12 小时 / L3 = 8 小时，时薪 17109 → 25664）。
4. 一次完整同步 = 4 站点 × 3 等级 = **12 次请求 = 12 次资源**，实测写入 441 条记录。

### 2.2 实测记录（2026-10-12，用户已开通账户）

在内置浏览器中直接请求接口，观察到两点：

1. **计费实测**：`item_price_all` 消耗 **20 次**（剩余 3,000 → 2,980），`day` 价格曲线消耗 **1 次**（2,980 → 2,979），
   与文档口径完全一致。累计消耗资源可在控制台「基础数据接口」页查看。
2. **响应无法直接查看**：浏览器把对 `/workApi/*` 的顶层导航判定为需拦截的资源（`ERR_BLOCKED_BY_CLIENT`），
   请求已送达服务端并已计费，但返回内容不渲染。因此**不能用浏览器直接读接口响应**；
   验证真实数据结构应在 M6 通过项目自身的 `DeltaDataSource`（Token 从 `.env` 读取）进行。

## 三、MVP 需要的接口

### 3.1 全物品基础信息库

`GET /v1/sjz_api/item_info_all`

| 字段 | 含义 |
| --- | --- |
| `oid` | **第三代数据 ID**（其他接口用它），不可交易时为 0 |
| `id` | 第二代数据 ID（已不适用，仅对照） |
| `objectID` | 三角洲官方小程序 ID |
| `objectName` | 物品名称 |
| `primaryClass` / `secondClass` / `secondClassCN` | 一/二/三级分类（如 `ammo` / `6.8x51mm` / `ammo6.8x51`） |
| `grade` | 等级（0~6） |
| `is_get` | 是否可在交易行交易，0=不可交易 1=可交易 |
| `pic` | 图片 URL |
| `width` / `length` | 占格宽高 |
| `desc` / `detail` | 文本介绍 / 扩展参数（detail 为 JSON 字符串） |

### 3.2 全物品最新价格

`GET /v1/sjz_api/item_price_all?isZb=0`

| 字段 | 含义 |
| --- | --- |
| `id` | **第三代数据 ID**（对应 3.1 的 `oid`） |
| `tid` | 第二代数据 ID |
| `price` | 当前价格 |
| `price_start` | 今日最初价格 |
| `bl` | 今日涨跌比例 |
| `day_3_price` / `day_3_bl` | 3 日价格 / 涨跌幅 |
| `day_7_price` / `day_7_bl` | 7 日价格 / 涨跌幅 |
| `day_30_price` / `day_30_bl` | 30 日价格 / 涨跌幅 |
| `is_get_time` | 价格更新时间戳 |
| `zb_price` | 战备值（每周二 10:00 前人工更新） |

> `isZb=1`（战备数据）文档标注为【暂不开放】。

### 3.3 全物品列表 / Top 排行（分页）

`GET /v1/sjz_api/item_list?lx=list&p=1&limit=10&types=acc&top=1-1`

- `lx`：`list` 列表 / `top` 排行
- `p`：页码；`limit`：每页 10~20
- `types`：`zhanbei`、`acc`、`ammo`、`gun`、`collection`、`consume`、`helmet`、`armor`、`bag`、`chest`、`key`（为空默认钥匙卡）
- `top`：`1-x` 今日涨跌、`2-x` 金额、`3-x` 价值、`5-x` 3 日涨跌、`7-x` 7 日涨跌、`30-x` 30 日涨跌（`-1` 小到大，`-2` 大到小）
- `n`：模糊搜索（≤40 字符）、`mid`：地图筛选（1 大坝 2 航天 3 长弓 4 巴克什 5 潮汐监狱）、`grade`：等级、`mtype`：收集品子类
- 额外字段：`ShopSellType`（推荐出售方式：方式名 / 等级 / 秒出价格）；`types=zhanbei` 时增加 `zb_price`、`zb_jz`、`zb_bl`

### 3.4 历史价格曲线

| 接口 | 参数 | 返回 | 覆盖范围 |
| --- | --- | --- | --- |
| `GET /v1/sjz_api/minute` | `id` | `data.a`(时间标签) / `data.b`(价格) / `data.zb` | 24 小时，分钟刻度，最多 1440 点 |
| `GET /v1/sjz_api/hour` | `id` | 同上 | 72 小时（含未来价值预测） |
| `GET /v1/sjz_api/day` | `id` | `data.a` / `data.b` / `max` / `maxD` / `min` / `minD` | 7 / 30 / 45 天，天刻度 |

`a` 与 `b` 是等长数组，按下标一一对应。

## 四、待用户确认 / 待真实 Token 验证

### 4.0 免费数据源现状（2026-10-12 核实）

数据帝曾提供**免费开源数据**：仓库 [orzice/DeltaForcePrice](https://github.com/orzice/DeltaForcePrice)，
文件 `price.json`，每 10 分钟推送一次，字段为 `id / name / price / secondClassCN / is_get_time`。

**该数据已于 2026-01-11 停更，不可用。**

实测核实：

| 项 | 值 |
| --- | --- |
| 仓库 README 停用通知 | 「因业务调整（哈夫克的重拳），将于 2026年1月11日 停止数据更新」 |
| `price.json` 最新采样时间 | 2026-01-10 23:19（含 1246 条记录） |
| 仓库最后一次提交 | 2026-01-15 07:15（提交信息：`fix`） |
| 距今 | 约 275 天 |

线上 API 的付费性质：所有接口文档均标注「资源扣除逻辑」，需在 `https://orzice.com/work/`
控制台「开通服务」后获取 Token，文档中**未提及免费额度或试用**；未开通时返回 404。

结论：**数据帝当前没有可用的免费数据通道**，只能走付费 API。项目在 M6 之前全程使用
`MockDataSource`，付费与否不影响 M1~M5 的开发与验证。

各接口的资源单价对比（用于选择最省资源的采集路径）：

| 接口 | 单次资源 | 是否一次拿到全部物品 |
| --- | --- | --- |
| `item_price_all` | 20 | 是（2000+ 物品一次返回） |
| `item_list_pro` | 1 | 否（分页，每页 10~20 条） |
| `item_list` | 10（按官方示例反推） | 否（分页） |
| `minute` / `hour` / `day` 曲线 | 1 | 单物品 |
| `item_info_all` | 20 | 是 |

因此**全量快照仍应走 `item_price_all`**：虽然单次 20 资源看似贵，但一次拿全；换成
`item_list_pro` 需要 60+ 次分页请求，反而更贵。

### 4.1 其余待确认项

1. **买价与卖价的字段来源**：上述接口只暴露单一 `price` 字段，没有区分买价/卖价。需要确认：
   - 数据帝是否有提供买/卖双价的接口（例如高级接口或官方小程序接口 `playerhub.df.qq.com`）；
   - 若要双价，`price` 应记作哪一侧（最低挂单价 or 卖出到手价）。
2. **`price` 的口径**：是交易行最低挂单价、近期成交价，还是官方小程序展示价？是否需要扣除手续费？
3. **Token 与开通范围**：需要你提供可用 Token，并确认已开通 `item_info_all`、`item_price_all`、`minute/hour/day` 这几个接口。
4. **资源次数余额与上限**：是否有每日总量上限？按每日 4 次全量采集约消耗 80 次/天，是否可接受？
5. **历史曲线接口是否计入 MVP**：若可用，`/api/items/{id}/history` 可以直接透传真实曲线（更精确），也可以只用我们自己积累的快照（更省资源）。当前设计用后者，接口已预留切换空间。
